================================================================================
PEZKUWI BLOCKCHAIN CITIZENSHIP APPROVAL FLOW - QUICK REFERENCE
================================================================================

KEY INSIGHT: The flow is DECOUPLED - identity-kyc pallet does NOT directly 
call tiki pallet. Instead, tiki polls KYC status via hooks.

================================================================================
STEP-BY-STEP FLOW
================================================================================

1. USER REGISTERS IDENTITY
   ├─ set_identity(name, email)
   └─ Storage: IdentityInfo created

2. USER APPLIES FOR KYC
   ├─ apply_for_kyc(ipfs_cids, notes)
   ├─ Storage: KycStatus = Pending
   ├─ Storage: PendingKycApplications created
   └─ Storage: Deposit reserved

3. KYC REVIEWER APPROVES (ROOT ORIGIN)
   ├─ approve_kyc(user)
   ├─ Storage: KycStatus = Approved
   ├─ Storage: PendingKycApplications removed
   └─ Storage: Deposit unreserved

4. AUTOMATIC HOOK (Tiki Pallet)
   ├─ on_initialize(block_number)
   ├─ check_and_mint_citizen_nfts()
   ├─ Scans all KYC-approved users
   └─ Calls mint_citizen_nft_for_user() for each

5. NFT MINTED & CITIZENSHIP GRANTED
   ├─ pallet-nfts::mint(collection=0, item_id, owner)
   ├─ lock_nft_transfer(collection, item_id)
   ├─ grant_role(Hemwelatî) [10 points]
   ├─ update_nft_metadata() → {"citizen":true,"roles":1,"score":10}
   ├─ Storage: CitizenNft[user] = item_id
   ├─ Storage: UserTikis[user] = [Hemwelatî]
   └─ Event: CitizenNftMinted

RESULT: User is now a citizen with voting rights!

================================================================================
KEY FUNCTIONS BY PALLET
================================================================================

IDENTITY-KYC PALLET
├─ set_identity(name, email) - Register identity
├─ apply_for_kyc(cids, notes) - Submit KYC docs
├─ approve_kyc(who) - Approve application
└─ revoke_kyc(who) - Revoke approved KYC

TIKI PALLET - EXTRINSICS
├─ force_mint_citizen_nft(user) - Admin override
├─ apply_for_citizenship() - User request (requires KYC approved)
├─ grant_tiki(who, tiki) - Admin grants role
├─ revoke_tiki(who, tiki) - Admin removes role
├─ grant_elected_role(who, tiki) - Voting grants role
└─ grant_earned_role(who, tiki) - Exam/test grants role

TIKI PALLET - HOOKS
└─ on_initialize() → check_and_mint_citizen_nfts()

WELATI PALLET - REQUIRES CITIZENSHIP
├─ Elections (requires Hemwelatî to vote)
├─ Appointments (calls grant_tiki for roles)
└─ Collective decisions (uses TikiScoreProvider)

================================================================================
STORAGE SCHEMA
================================================================================

IDENTITY-KYC
├─ Identities[AccountId] = IdentityInfo {name, email}
├─ KycStatuses[AccountId] = KycLevel (NotStarted | Pending | Approved | Revoked)
└─ PendingKycApplications[AccountId] = KycApplication {cids, notes}

TIKI
├─ CitizenNft[AccountId] = u32 (NFT Item ID)
├─ UserTikis[AccountId] = BoundedVec<Tiki> (user's roles)
├─ TikiHolder[Tiki] = AccountId (for unique roles like Serok)
└─ NextItemId = u32 (counter for NFT IDs)

TIKI SCORE SYSTEM

Hemwelatî (Citizenship):         10 points (auto-granted)

================================================================================
ROLE ASSIGNMENT TYPES
================================================================================

AUTOMATIC  → Hemwelatî (granted with citizenship)
APPOINTED  → Admin grants (Wezir, Dadger, etc.)
ELECTED    → Voting system (Serok, Parlementer, SerokiMeclise)
EARNED     → Tests/exams (Axa, Mamoste, Rewsenbîr)

Important: Role assignment type must match grant method!
❌ Cannot grant "Elected" role via admin function
✓ Can only grant "Appointed" roles via admin

================================================================================
CRITICAL GAPS / MISSING FEATURES
================================================================================

❌ CRITICAL
1. No explicit citizenship revocation extrinsic
   - KYC revocation doesn't cascade to citizenship NFT
   - Admin cannot revoke Hemwelatî directly
   
2. No cross-pallet event listener
   - Tiki polls KycStatuses every block (inefficient)
   - No callback from identity-kyc when KYC approved
   
3. No automatic governance integration
   - When citizen minted, not auto-registered to vote
   - Manual voter registration needed

❌ HIGH PRIORITY
4. No KYC review workflow
   - Approval is instant (single extrinsic)
   - No multiple reviewer support
   - No rejection reason tracking
   
5. No identity update mechanism
   - Once set, identity is immutable
   - User cannot change name/email
   
6. No citizenship expiry
   - Citizenship is permanent once granted
   - No renewal or time-based revocation

❌ MEDIUM PRIORITY
7. No identity privacy (GDPR concern)
   - Name & email stored plain on-chain
   - Should use hashing or off-chain storage
   
8. No citizenship transfer/account migration
   - If private key lost, citizenship lost
   - No recovery mechanism

❌ MISSING TESTS
- Integration test: identity → kyc → citizenship → governance
- KYC revocation cascade test
- Role assignment after citizenship test
- Concurrent KYC application test

================================================================================
SECURITY CONSIDERATIONS
================================================================================

IMPLEMENTED ✓
├─ Deposit mechanism (KYC spam deterrent)
├─ Origin validation (only authorized can approve)
├─ Non-transferable NFTs (cannot sell citizenship)
├─ State machine (KYC status transitions)
├─ Unique roles enforcement (only one Serok)
└─ NFT locking via pallet-nfts

POTENTIAL RISKS ⚠️
├─ Block scanning inefficiency (scans all users every block)
├─ No audit trail (who approved KYC not logged)
├─ Identity privacy (name/email on-chain)
├─ No slashing for KYC revocation (no economic penalty)
└─ Account recovery missing (lost key = lost citizenship)

CALL SEQUENCE EXAMPLE
================================================================================

Day 1: Alice.set_identity("Alice Smith", "alice@example.com")
       → Event: IdentitySet

Day 1: Alice.apply_for_kyc(["QmHash1", "QmHash2"], "Documents")
       → Event: KycApplied
       → KycStatus: NotStarted → Pending
       → Deposit reserved: 100

Day 5: Root.approve_kyc(Alice)
       → Event: KycApproved
       → KycStatus: Pending → Approved
       → Deposit unreserved: 100
       → PendingApplications[Alice] removed

Day 5, Block 100 (automatic):
       → on_initialize()
       → check_and_mint_citizen_nfts()
       → mint_citizen_nft_for_user(Alice)
       → NFT Item #42 minted to Alice
       → NFT locked (non-transferable)
       → Hemwelatî role granted (10 points)
       → Event: CitizenNftMinted { who: Alice, nft_id: 42 }

NOW:   Alice.is_citizen() → true
       Alice.get_tiki_score() → 10
       Alice.can_vote_in_governance() → true
       Root.grant_tiki(Alice, Wezir) → Alice.get_tiki_score() → 110
